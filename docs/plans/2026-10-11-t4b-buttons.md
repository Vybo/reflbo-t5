# T4b: the T5's four buttons — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The T5's buttons follow their order on the board's edge, Back (IO0), Up (IO35), Enter (IO34), Down (IO39), with up/down and enter/escape navigation on the dashboard and in the menu, as DT13 sets out; the RLCD keeps its two buttons exactly as they are.

**Architecture:** One pure table per board (`components/ui/ui_controls.c`) turns a button and a gesture on a screen into an action; `main/app.c`'s button handler executes the action instead of testing buttons itself. The menu gains up, down and escape keys. The T5's board code reads four buttons (two of them new: IO39, and IO0 only between panel updates), names them by role, and its profile says it has four, which picks the four-button hint lines.

**Tech Stack:** C17, ESP-IDF 5.5.5, Unity host tests, the T5 at the bench with the owner's hands.

**Spec:** `docs/specs/2026-10-06-t5-board-design.md` r10: DT13, §8.3 (the design, verbatim the source of truth), §2.5 gotcha 2, §9 (`btn`).

## Global Constraints

- The RLCD's behaviour, goldens and snapshot stay exactly as they are: its controls table reproduces `main/app.c`'s handler as it stands (Task 2 pins every row).
- Both boards build clean; host suite (`cmake --build build-host`, `ctest --test-dir build-host`) and web tests green; separate commands.
- The owner approves changed T5 renders (the hint lines) before their goldens are written (DT2).
- Board rules (AGENTS.md §10): MAC `34:ab:95:5e:5d:58` on `/dev/cu.usbserial-52D60046741` before flashing, `-b 230400`; never erase.
- Commits: Conventional Commits, no trailers, nothing about tools or assistants.

## Review Focus

1. **A Back press during a panel update** (IO0 is the strobe then): ignored, never a gesture from the strobe's own edges; if it's still held when the update ends, the next update is clean. Pinned in Task 4 (pause/resume) and checked at the board (Task 6).
2. **The RLCD:** every gesture on every screen does what it does today. Pinned row by row in Task 2.
3. **Down or Back on a deep-sleeping T5** does nothing (they can't wake it); after any press the board stays awake 10 s, so they work as the next press. Checked at the board.
4. **The menu's edit and confirm modes with the new keys:** Up +, Down −, Enter saves or confirms, Back and a held Enter cancel; nothing confirms by accident. Pinned in Task 1.
5. **Up on the dashboard with presets outside the cycle:** it skips what Down (next) skips, backwards, and stays put with none to go to. Pinned in Task 1.

### Task 2: The controls tables

**Files:** create `components/ui/include/ui_controls.h`, `components/ui/ui_controls.c`; `components/ui/CMakeLists.txt` and `test/host/CMakeLists.txt` (sources); `components/ui/include/ui_profile.h` and both profiles (`uint8_t buttons;`: 2 on the RLCD, 4 on the T5); test `test/host/test_ui_controls.c`.

**Interfaces — produces:**

```c
typedef enum { UI_BTN_KEY, UI_BTN_BOOT, UI_BTN_DOWN, UI_BTN_BACK } ui_button_t; /* the T5: KEY's pin is Enter, BOOT's Up */
typedef enum { UI_GESTURE_SHORT, UI_GESTURE_DOUBLE, UI_GESTURE_LONG } ui_gesture_t;
typedef enum { UI_SCREEN_DASHBOARD, UI_SCREEN_MENU, UI_SCREEN_CONFIG, UI_SCREEN_FIRST_RUN, UI_SCREEN_CRITICAL } ui_screen_t;
typedef enum {
    UI_DO_NOTHING, UI_DO_PRESET_NEXT, UI_DO_PRESET_PREV, UI_DO_CYCLE_TOGGLE, UI_DO_MENU_OPEN, UI_DO_REFRESH,
    UI_DO_ALWAYS_TOGGLE, UI_DO_CONFIG_ENTER, UI_DO_MENU_KEY, UI_DO_CONFIG_KEY, UI_DO_CONFIG_EXIT,
    UI_DO_FIRST_RUN_CONTINUE, UI_DO_FIRST_RUN_MENU, UI_DO_RESAMPLE,
} ui_do_t;
typedef struct { ui_do_t what; ui_menu_key_t key; /* for UI_DO_MENU_KEY */ } ui_control_t;
/* By the profile's buttons (2: the RLCD, upstream §5.6; 4: the T5, T5 spec §8.3). */
ui_control_t ui_controls(ui_screen_t screen, ui_button_t button, ui_gesture_t gesture);
```

The RLCD's table is `main/app.c`'s handler today: menu KEY short/double → NEXT, KEY long → SELECT, BOOT short/double → BACK, BOOT long → EXIT; config KEY short → CONFIG_KEY, BOOT long → CONFIG_EXIT, else nothing; critical any → RESAMPLE; first run BOOT long → CONFIG_ENTER, KEY short → CONTINUE, KEY long → FIRST_RUN_MENU, else nothing; dashboard KEY short → PRESET_NEXT, KEY double → CYCLE_TOGGLE, KEY long → MENU_OPEN, BOOT short → REFRESH, BOOT double → ALWAYS_TOGGLE, BOOT long → CONFIG_ENTER. The T5's is §8.3: menu Up short/double → UP, Down short/double → DOWN, Enter short/double → SELECT, Enter long → ESCAPE, Back any → ESCAPE, Up/Down long → nothing; config Enter short → CONFIG_KEY, Back any or Enter long → CONFIG_EXIT; critical any → RESAMPLE; first run Enter short → CONTINUE, Enter long → FIRST_RUN_MENU, Up long → CONFIG_ENTER; dashboard Up short → PRESET_PREV, Down short → PRESET_NEXT, Enter short → REFRESH, Enter long → MENU_OPEN, Up long → CONFIG_ENTER, Enter double → ALWAYS_TOGGLE, Down double → CYCLE_TOGGLE, Back any → NOTHING.
