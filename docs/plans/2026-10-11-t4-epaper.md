# T4: e-paper behaviour and power — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The T5 updates its panel the e-paper way: fast updates of what changed (DU or GL16), a clean one every `display.clean_after` updates and at the moments the spec names, across deep-sleep wakes without artifacts; night sleep keeps the dashboard with a moon and the end time; no seconds; the setting on the menu and the web page with its sentence; the power measured.

**Architecture:** A pure update policy in `components/epaper` (the change between two 4 bpp frames: its box and whether it is black and white only; the mode to use) decides every update; `display_t547.c` runs it through epdiy's high-level state, whose back buffer is what the panel shows. Across deep sleep PSRAM is lost, so the app keeps the time it last drew for (`shown_at`) in its RTC-RAM snapshot, draws that frame again after a warm wake, and the display adopts it as the panel's state when its CRC matches the one it kept; otherwise the next update is clean. The rest is settings, menu, web and UI work on both boards, with the RLCD unchanged.

**Tech Stack:** C17, ESP-IDF 5.5.5, epdiy 2.1.3 (vendored, high-level API), Unity host tests, plain JS with Node's test runner, the T5 at the bench with the owner's meter.

**Spec:** `docs/specs/2026-10-06-t5-board-design.md` (r8): §5.3 updates, §5.4–5.6 panel power, the previous frame, night sleep; §8.5 power; §9 settings, menu, web, console; §11 T4; §12 refresh currents, ghosting, a cold boot draws twice, RainViewer's loop re-measured.

## Global Constraints

- The RLCD's goldens stay byte-identical; both boards build clean with no new warnings (`tools/idf.sh build`, `REFLBO_BOARD=t5 tools/idf.sh build`); the RLCD's behaviour is unchanged (its display gets the new calls as no-ops).
- Host suite: `cmake --build build-host`, then `ctest --test-dir build-host`; web: `node --test test/web/test_app.mjs`. Separate commands, not `sh -c`.
- `display.clean_after`: 1–240, default 60, its default in `components/storage` (AGENTS.md §8), "flashes clean every Nth update": every `clean_after`th update is a clean one (1: every update clean).
- Clean updates (spec §5.3): every `clean_after`th update; a preset switch (KEY, the cycle, the schedule); leaving the menu or the config screen (`display_set_fast(false)`); the end of night sleep and a night peek; `panel clean`; a cold boot; whenever the panel's frame isn't known. `display_set_fast(true)` updates are fast and not counted.
- Fast update: DU when every pixel that changes is black or white before and after, GL16 otherwise; only epdiy's dirty lines are driven.
- The T5 never draws seconds; the web page says so on the T5.
- The owner approves T5 renders before their goldens are written (DT2): the night mark and the seconds-less Focus clock.
- Board rules (AGENTS.md §10): flash only `/dev/cu.usbserial-52D60046741` after reading MAC `34:ab:95:5e:5d:58`, `-b 230400`; never erase; back up before a test that changes the board's data and restore after; the owner's web password only through the owner typing it into the CDP Chrome window, flash before asking, log out after.
- Commits: Conventional Commits, imperative, no trailers, nothing about tools or assistants.

## Review Focus

1. **A wake whose data changed after the last commit** (a sync finished, then the board slept without drawing): the rebuilt frame's CRC differs, so the update is clean, never a fast update against a wrong back buffer. Pinned by the policy test (unknown → clean) and checked at the board (Task 9: the log's "shown frame" line).
2. **A failed update** (epdiy's RAM budget refused it, or a draw error after the clear): the panel's frame is no longer known, so the next update is clean and the counter isn't advanced; nothing is skipped as "unchanged". Pinned in Task 2's policy tests; wired in Task 3.
3. **`clean_after` reached while nothing changed:** no update runs (no flash for an unchanged frame); the clean comes with the next change. Pinned in Task 2.
4. **The menu or the radar's loop** (fast, uncounted) **ending:** the next commit is clean even when the frame didn't change, so their ghosts go. Pinned in Task 2 (`clean_next` with no change → clean).
5. **The RLCD:** every new display call is a no-op there, no seconds or menu item changes, its catalogue's capabilities unchanged. Pinned by the RLCD goldens, `test_ui_catalog` and `test_ui_menu` on the RLCD profile.

### Task 2: The update policy, pure

**Files:**
- Create: `components/epaper/epaper_update.c`, `components/epaper/include/epaper_update.h`
- Modify: `components/epaper/CMakeLists.txt` (SRCS), `test/host/CMakeLists.txt` (the new test)
- Test: `test/host/test_epaper_update.c`

**Interfaces:**
- Produces:

```c
typedef struct {
    bool any;        /* some pixel differs */
    bool bw_only;    /* every differing pixel is black (0) or white (15) before and after */
    int16_t x, y, w, h; /* the differing pixels' bounding box; all 0 when !any */
} epaper_change_t;
/* before/after: w x h at 4 bpp, two pixels a byte, the even pixel in the low nibble (epdiy's layout). */
void epaper_change(const uint8_t *before, const uint8_t *after, int w, int h, epaper_change_t *out);

typedef enum { EPAPER_NONE, EPAPER_CLEAN, EPAPER_DU, EPAPER_GL16 } epaper_mode_t;
typedef struct {
    bool known;            /* the panel's frame is known (epdiy's back buffer) */
    bool clean_next;       /* a preset switch, leaving the menu, the end of a night, `panel clean` */
    bool fast;             /* display_set_fast(true): not counted */
    uint16_t since_clean;  /* counted updates since the last clean one */
    uint8_t clean_after;   /* every Nth update is clean, 1..240 */
} epaper_policy_t;
epaper_mode_t epaper_choose(const epaper_policy_t *p, const epaper_change_t *c);
/* After an update of `mode` ran: ok, or failed. */
void epaper_after(epaper_policy_t *p, epaper_mode_t mode, bool ok);
```

Rules: `!known || clean_next` → CLEAN, even without a change; else no change → NONE; else `!fast && since_clean + 1 >= clean_after` → CLEAN; else `bw_only` → DU, otherwise GL16. `epaper_after`: ok CLEAN → `known = true, clean_next = false, since_clean = 0`; ok DU/GL16 → `since_clean++` unless `fast`; a failure (any mode) → `known = false` (the panel's state is uncertain; the next is clean), `since_clean` unchanged.
